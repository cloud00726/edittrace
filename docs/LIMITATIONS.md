# 已知限制

- 同步内部格式仍为 EditTrace JSONL v1。现有适配器仅支持固定 JSON-RPC trace 方言，显式解析初始化结果或标记片段假设；不支持任意编辑器日志、带时间前缀文本日志或非 UTF-16 会话。
- VS Code 记录文档事件及实际文本，不截获其他插件通信；重命名预览仅验证文本投影，不能验证文件资源操作及提供者原始版本约束。缺少格式化编辑可能意味着已格式化或没有提供者。
- 只验证文档同步子集。忽略的方法会计数，未声称验证全 LSP 或服务器实现。
- 没有真实服务器缺陷发现、用户量、生产部署或性能优胜的声明。原 8 类演示为合成；examples/real-world 为真实宿主采集与分别标注的故障注入，不能替代真人需求验证。
- Windows native 已本地验证；基线 79cde2a 的 Windows/Linux CI 已通过（运行 38738218872），后续改动以对应 Actions 为准。本机没有 Linux 执行环境。
- 当前全文替换与行索引 O(n)。已测耗时见 validation-results.json；峰值内存没有测量。
- 非法行和代理对中间边界采用保守策略，不模仿某些库的宽松处理。JSON 不接受不成对代理项字符串。
- 一个检查点失败不定位唯一根因；没有独立服务端快照不能判断服务端内部状态。
- replay 的 --at-seq 要求该记录存在；输入 seq 可以有间隙，不能对不存在的序号输出一个假定快照。
- 输出文件和导出目录不覆盖现有目标。导出中途 IO 失败可能留下部分新目录，需用户检查后处理。
- 证据包默认完整前缀，新增可选按文档筛选并重验完整 finding，保留物理行号；不自动寻找最短序列或脱敏。verify 校验复现一致性，不是密码学真实性证明。用例封装若写入中途失败可能留下部分新目录。
- audit --omit-excerpts 只隐藏固定文本摘录，URI、label、meta 仍可能含敏感数据；不会修改原始会话、replay 或导出包。
- GitHub 仓库已公开。早期格式反馈后又收到用户提供的实质驳回意见；本轮尚未重新申报、提交验收或发布 Mooncakes 包。可下载预览与远程 Windows/Linux CI 状态以实际 Releases/Actions 为准，不能把配置存在当作运行通过。
- 新工作流 JSON/用例输入上限 8 MiB；导入源上限 64 MiB、单行 8 MiB；每文档 4 MiB、每批最多 10000 编辑、最多 256 文档。扩展录制上限约 7 MiB/100000 记录/64 文档，实际写出仍受 8 MiB 输入限制；资源不足明确失败。
- 实际 VS Code 宿主只验证了 1.138.0；引擎声明下限不代表全部版本均经测试。Windows 发行包已本地运行，Linux 新流程需远程 CI 验证。尚未证明普通用户五分钟首次接入目标。
