# 0.2.0 发布前审查与演练

2026-10-20。审查范围：此前未提交的整改源码、扩展、用例、打包和 CI。由 Codex 在本地审查并复核，不冒称独立第三方审计。

## 发现与处理

| 问题 | 修复与验证 |
|---|---|
| 版本不匹配时提前跳过 edits 结构和 actual URI 校验，损坏输入可能被报成完整的版本问题 | 先校验全部编辑结构、actual 对应关系和基线资源上限，再检查版本；新增组合失败回归 |
| 每个 at_seq 文本断言重新回放整个前缀，长录制的用例成本随断言数重复增长 | 单次回放按请求序号保存所需 URI 的快照；新增 1500 步和 1500 个独立期望的长录制回归；拒绝 0/负 at_seq |
| JSON-RPC 后续请求合法复用已完成 initialize 的 id，会被误判成重复初始化响应 | 区分初始化完成后的 id 复用与初始化未完成的冲突；增加日志变体回归 |
| 有初始化响应就标为 full，容易把“观察到初始化”误解为“完整捕获” | 固定声明 fragment，单独记录 initialization_observed 与编码依据 |
| CI 提前失败时，新增报告文件可能沿用仓库中上次本地成功结果 | 开始时清理本次将上传的全部生成验证报告；历史宿主实采作为独立记录，不冒充 CI 运行 |
| 新旧核心都显示 0.1.0，不利于识别实际支持能力 | 核心、module 和扩展统一到 0.2.0，打包从实际二进制读取并核对版本；verify 继续接受旧 0.1.0 证据包 |

## 已执行的本地复核

- 完整 native/干净目录验收：337 项断言；新增工作流 80 项；19 个 native 测试，原 500 会话/4000 检查点不变。
- Node：5 项传输/已捕获顺序回归通过；工具链与 CI 支持：6 项通过。
- VS Code 1.138.0：14 项真实宿主检查，包括用户 start/stop、格式化命令、差异、跨文件重命名及回归草稿执行。
- 保存草稿与用户命令共享实现，实测写入测试目录并运行；保存/确认对话框未由人点击，不把自动化演练当作真人主观体验。
- 预览保持只读；真实编辑和提供者应用限制在测试工作区。Node 调用使用参数数组、可取消/超时，未引入运行时 npm 依赖。

当前结果文件为 docs/*-validation.json；实际 host 与已安装 VSIX 复核应区分 source/packaged。远程 CI、可下载发行包和日常配置安装结果将在 GitHub 发布后另行记录，不能提前宣称完成。

## 保留边界

只支持 UTF-16/纯文本编辑；rename 只验证稳定 API 的文本投影。自动最小复现、全部资源操作和更多编辑器不在本轮。未发现或宣称第三方漏洞、需求规模或真人持续采用。没有要求清空原工程、改系统 PATH 或重建独立 oracle。
