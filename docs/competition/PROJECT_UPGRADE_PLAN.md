# EditTrace 0.5.0 后续优化与验收方案

基线为本地与 GitHub 一致的 [a724ff0](https://github.com/cloud00726/edittrace/commit/a724ff08543d4d9b6d914b3aba77ae9d64028830)。目标是让外部维护者能下载固定版本，验证自己本次构建的插件，并从 CI 报告看清行为变化或环境故障。按 P0、P1、P2 执行，每阶段提交实现、验证证据和必要文档。

## 核查结论

| 范围 | 已验证 | 缺口 |
|---|---|---|
| 文本核心 | 原生 Windows、Ubuntu CI 通过。仓库保留 500 会话、4000 检查点的独立参考语料 | 文本能力继续受 UTF-16 和现有操作范围约束。版本升级应保护已有 case、suite、证据包 |
| 待测插件门禁 | 本地打包版和 GitHub Windows 宿主已运行合成正确、故障、修复 VSIX，覆盖格式化、跨文件重命名、客户端同步 | Ubuntu 在第一个正确版本的三个场景都报告宿主未完成，退出 2。远程日志缺少宿主退出状态和启动诊断，根因待确认 |
| 外部使用 | 仓库外 Windows 目录已验证打包入口，独立消费者工作流示例已提供 | 独立仓库的真实远程门禁、真实第三方版本与 MoonBit 提供者仍缺实测 |

## P0 恢复双平台门禁，明确判定依据

1. **先定位 Ubuntu 宿主失败。** 在现有固定版本、Xvfb 和独立 profile 中复现。按下载、安装、启动、扩展激活、请求、报告写出分阶段记录。公开摘要仅保留阶段、退出状态、宿主版本和经过筛选的错误分类。启动失败的详细日志留在本地或经脱敏后上传。核对 Linux 显示环境、Electron 依赖和沙箱诊断，检查进程退出后报告是否写完。根据日志修复，保持验证失败时阻断门禁。
2. **统一场景和报告校验。** 对 suite、operation、文件条目和宿主报告校验类型、必需字段及版本。路径用同一规则处理大小写冲突、保留名和目录冲突。外层结果要与请求中的场景名、宿主版本、候选标识和完成状态一致。记录报告协议版本和失败阶段。MoonBit 校验同一文档的独立宿主文本与断言观察使用同一份数据，避免两套字段各自通过。
3. **分清行为回归与运行失败。** 缺失提供者、版本不符、未产生可核实结果、超时或证据不完整返回 2。已确认执行且实际输出偏离预期返回 1。现有空编辑统一无法通过，先保持此限制。仅在新增适配器能够证明实际执行的前提下，允许场景声明空编辑是正确行为。
4. **保护宿主与报告。** 候选 VSIX 在当前进程权限下运行。CI 以普通低权限任务和隔离文件目录运行，限定候选来源和依赖哈希。检查超时能清理启动的进程树。默认报告使用固定诊断字段，完整宿主日志与工程文本单独保存。限制读取、日志和运行时间。候选无效、宿主超时、旧报告残留、报告字段缺失均应有稳定失败结果。

**验收**：同一新提交的 Windows 和 Ubuntu 宿主均得到正确版、故障版、修复版的 `0 → 1 → 0`。漏改负例指向引用文件。至少保留错误哈希、错误宿主版本、缺失提供者、超时和不完整报告的阻断证据。原生、扩展和独立参考测试继续通过。构建工具或工作流配置变化也应触发相应检查。

## P1 证明真实消费者能拦截发布

1. **独立消费者远程 CI。** 使用仓库外的项目与固定 EditTrace 下载物。消费项目持有用例与审核基线，验证本次构建的 VSIX。直接将退出码设为门禁结果，保留真正失败的 job 与修复后通过的 job。EditTrace 自测中“负例失败符合预期”的绿灯保留为自测证据。
2. **引入至少一个真实工具链。** 优先选能合法取得固定制品、可稳定安装、有公开可复现行为差异的版本对。相同工程、宿主、设置和断言运行两个版本并留存输出。真实历史回归找不到时，真实提供者运行与合成注入分别留证。针对 MoonBit 先核实扩展与语言服务器的安装方式、版本及授权条件，再锁定一个实际格式化或重命名场景。
3. **保证提供者归属。** 当前宿主通过 VS Code 通用命令请求结果。扩展激活成功、语言已声明只能证明候选存在。为多提供者或依赖场景建立可证明归属的受控适配器，固定候选和依赖哈希，并用缺失候选、内建提供者代答等负例证明不会误报通过。客户端同步继续用真实操作和快照验收。若需要证明语言服务器处理了同步，增加可独立观察的服务器输出或固定协议测试适配器。
4. **降低接入成本。** 新增从已有小工程创建待审核场景的入口和 `doctor` 预检，展示候选、宿主、依赖及支持范围。为配置文件、LF/CRLF、emoji、多文件和禁止改动路径提供例子。基线更新展示差异并单独评审，CI 验证前后基线哈希一致。先做命令行模板，再按实际试用反馈决定是否加入扩展界面。

**验收**：独立消费者仓库能从可固定、可校验的制品开始复跑。交付同一用例下的通过、失败、修复链接及版本清单。至少一项证据来自真实第三方工具。MoonBit 集成按实际通过的操作列出，其注册表验证单独记录。

## P2 完成发行、维护和性能收尾

1. **发行与证据对齐。** P0 兼容修复可作为 0.5.x，新增场景契约或适配能力再确定下一功能版本。用同一干净提交生成 Windows 和 Linux CLI、VSIX、执行器及 SHA-256。由 CI 产物做独立安装、消费和旧数据兼容验证。维护 Release、README、快速开始、申报材料和许可证来源，链接到能实际下载和复跑的版本。发布 GitHub Release、Mooncakes 或提交赛事材料依相应授权执行。
2. **公开 API 与供应链。** 校验公开 API 快照及 native/JS 独立消费。Mooncakes 先确认账户及 namespace，再按正式模块名检查干净消费与许可。CI 第三方 Action、VS Code 和候选依赖采用可审核的固定版本或摘要，更新后重新跑对应验证。
3. **先测量再优化。** 分别记录主机冷启动、VSIX 安装、提供者执行和 MoonBit 核心判断的耗时。批量场景先复用已验证的制品下载缓存，每个场景保留工程隔离。历史 1 MiB/1000 批量编辑约 13.67 秒来自旧的开发构建，只作剖析线索。用同构建模式、同输入、同硬件复测并记录峰值内存，再决定是否改文本算法。共享 CI 不采用未经测量的耗时阈值。
4. **留出长期维护入口。** 为每次公开发布记录支持矩阵、旧包兼容范围、已知限制与复现案例。试用记录包含首个门禁接入耗时、失败报告是否指出问题、遇到的接入障碍。申报描述引用相应真实证据。

**最终验收**：公开下载物和仓库标注同源，双平台宿主检查通过，独立消费可复跑，有真实版本证据与实际失败门禁，许可证和限制清楚。未达到的外部条件在交付清单中保留实际状态。首次实施从 Ubuntu 宿主诊断开始。
