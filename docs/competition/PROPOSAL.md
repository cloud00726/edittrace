# EditTrace：LSP 增量文档同步审计与复现工具

**问题与用户**：编辑器与语言服务器间的文档同步包含连续编辑、文档版本和 Unicode 坐标。出现补全位置异常或内容不一致时，原始消息难以人工追踪。EditTrace 为语言服务器和编辑器插件开发者提供离线、可解释、可重放的检查流程。

**实现内容**：使用 MoonBit 实现规范化 JSONL 读取、UTF-16 编辑重放、多文档生命周期与版本审计、独立检查点比对和复现包导出。核心逻辑拆为可复用库，CLI 提供 audit、replay、export。14 条规则区分协议观察、产品保守策略和外部检查点证据。

**工程特点**：单通知事务化，失败不产生部分编辑；未知文本不被继续猜测；有效全文替换或重开可恢复。列坐标回退遵循协议；CR/LF/CRLF 与 emoji 边界有专门测试。证据包写入后重新读取验证目标指纹，保留完整上下文而不冒称最小复现。

**验证方案**：原生单元测试、8 类合成演示、CLI/资源限制验收与固定 Microsoft 参考实现对照。已生成 500 组合法会话、4000 个逐步检查点；当前实际验证结果以 docs/validation-results.json 为准。已记录固定参考版本的 CRLF 行索引缓存观察，生成器采用每次编辑后重建参考索引，避免生成无效后续位置。

**范围与价值**：首版限定 UTF-16 文档同步和自定义输入格式；不承诺完整 LSP 检查、自动采集或从客户端日志证明服务端内部错误。补足开发者工具链中“同步过程可审计、问题证据可复现”的细分能力。后续可增加日志适配器、真实服务器采集和自动精简。

**开源与交付**：仓库已按 MIT 公开，提供源码、README、示例、必要测试、CI 配置、来源与 AI 使用说明。已收到申报格式不支持的初审反馈；尚未完成重申报、验收或 Mooncakes 发布。
