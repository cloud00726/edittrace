# 本地 0.5.1 升级验证

基于公开提交 `a724ff0` 执行[优化方案](PROJECT_UPGRADE_PLAN.md)的本地工作。保留场景 v1 和冻结用例。新增宿主报告协议 2 与原生 observation v2，要求候选、运行请求和证据相互匹配。

| 任务 | 实际结果 |
|---|---|
| P0 宿主诊断 | 分开报告安装、启动、激活、请求、核心判定和报告校验。启动摘要记录退出状态与已识别提示，原始日志本地保存。执行器限制启动时间与日志输出，超时尝试终止进程树。 |
| P0 数据校验 | 拒绝跨平台路径冲突、重复键、错误参数、过期报告及不一致的完成状态。MoonBit 校验独立文本和最终观察一致。 |
| P0 Windows | 真实 VS Code 1.144.0 安装合成 VSIX。好版、漏改版、修复版得到 0、1、0。缺失格式化提供者和请求超时分别得到 2，报告各自的原因。 |
| P0 Ubuntu | 旧远程宿主失败的根因仍待确认。已核实本机有 Ubuntu 22.04 WSL，但缺 Xvfb。通过代理下载同版 VS Code 时 TLS 握手失败，直连 110 秒只下载约 37 MB，未得到可执行归档。CI 已增加依赖和启动诊断。 |
| P1 接入 | 新增 `--check-input`，在安装前验证场景、候选哈希及宿主版本。独立远程消费者与真实第三方、MoonBit 提供者的验证仍待完成。 |
| P2 测量与打包 | 本地记录每场景安装和宿主总耗时。Windows 0.5.1 候选由干净提交 `2d1a7b8` 生成，20 项发行检查通过。从仓库外使用解压后的执行器再次拦截漏改版，三个场景均返回 1。 |

完整干净目录验收 383 项通过。另运行执行器边界测试 6 项，涵盖报告身份、跨平台路径、超时及日志超限。Windows 运行摘要中的候选与基线哈希以及失败分类见 [provider-051-local-validation.json](../provider-051-local-validation.json)。

候选归档、校验和、发行验证及独立消费者报告保存在 `output/provider-0.5.1-local/`。本地发行验证文件包含安装路径。

Ubuntu 复验使用当前 CI 配置中固定的 VS Code 1.144.0。若再次失败，优先读取摘要的 `process_exit` 与 `hint`，并在可复现环境核对本地启动日志。根据证据修复后，以同一提交的双平台宿主 CI 作为关闭 P0 的依据。
