## 问题与改进

编辑器插件和语言工具会产生格式化、重命名及增量同步编辑。开发者需要确认这些范围能否作用于指定版本的文本、多个文件的应用结果是否一致，以及修复后如何持续检查。EditTrace 使用 MoonBit 实现文本变更预检、同步重放、实际快照比较与回归用例运行。本轮针对审查提出的场景狭窄、规范化输入门槛及复用不足，增加真实 JSON trace 导入、VS Code 本地录制和独立消费者示例，使 JSONL 成为内部格式。

## 三个完整场景

1. **格式化变更回归**：插件开发者取得格式化提供者编辑与原始文本，预检版本、范围和冲突；将预测结果与宿主实际应用后的文本比较，保存明确期望的用例，之后在 CI 重跑。仓库提供真实 JSON 格式化采集及版本过期注入，区分预检失败与成功复现。
2. **跨文件重命名验证**：语言工具维护者取得多文件文本编辑，逐文件检查同一基线上的编辑并比较实际结果。真实 TypeScript 样例涵盖定义和引用两个文件。VS Code 稳定接口仅暴露文本投影，因此报告明确不验证资源文件操作或提供者基线版本，不宣称重构语义正确。
3. **同步问题交接与回归**：开发者启动编辑器录制，取得打开基线、连续编辑和独立文本快照；停止后重放 Unicode、CRLF、批量编辑和撤销重做。问题可封装为可迁移用例，或导出经完整 finding 重验的同步证据包。真实宿主样例和人为漏事件用例分别展示正常与失败路径。

## 实现、复用与差异

核心解析、UTF-16 文本操作、同步状态机、批量编辑预检、断言与 CLI 使用 MoonBit；VS Code 扩展仅承担采集和宿主交互。批量 TextEdit 基于同一原文处理，与 didChange 顺序语义独立实现。提供带类型 Edit/FindingExpectation 接口、独立 MoonBit 消费者、case/suite 运行和 CI 示例。相对仅查看消息的工作流，实际新增的是自动计算文本、与宿主结果比较，以及可重跑交付；不宣称其他工具均无这些能力或整个工作流首次出现。

## 验证与边界

独立参考语料为固定 Microsoft textdocument 1.0.12 的 500 会话/4000 检查点；原有测试保持。新增真实 VS Code 1.138.0 宿主检查、实际 JSON-RPC 服务器 trace、三类可执行场景、CLI 错误/迁移检查和本地 Windows ZIP/VSIX 验证，结果见 docs/validation-results.json、examples/real-world/capture-evidence.json 与 docs/distribution-validation.json。故障注入不冒充第三方漏洞。暂仅 UTF-16/纯文本编辑子集；无服务器内存证明、真人需求规模或性能优胜声明。新远程 CI、真人试用、Mooncakes 发布和重新送审仍需分别完成。AI 协助已在 AI_USAGE.md 披露。
